# In Council: Hong Kong, 1960–1997

An interactive visualizer of who sat on Hong Kong's Legislative Council (立法局) and Executive Council (行政局), and who held the colony's senior official posts, on any day from 1 January 1960 to 30 June 1997. The Provisional Legislative Council of 1996–97 has its own tab.

**Site:** https://council.viet-huynh.com
**By:** [Viet Huynh](https://viet-huynh.com)

## What's in it
- Seats on any day, as cards or as a chamber diagram, with acting and provisional members
- Timeline: membership charts, play the years forward, compare two dates
- A page for each of the 426 people, with roles, dates and sources, at council.viet-huynh.com/people/
- Connections between council members and companies and institutions
- A printable poster of any council on any day
- The full dataset as CSV
- A list of what's missing (the site's Limitations page)

## How the site is built
Everything comes from one data file, `data/council-data.json`. The builder, `build.js` (plain Node, nothing to install), turns it into the finished site in `public/`:

- `public/index.html`: the visualizer, one self-contained file with the data inside it (its code is in `src/`)
- `public/people/<name>/index.html`: one page per person, readable by search engines without JavaScript
- `public/people/index.html`: the A–Z list of everyone
- `public/sitemap.xml`: every address, for search engines

To change anything: edit `data/council-data.json`, then in this folder run

    node build.js

It checks the data first and stops with a plain message if something points at a person, organization or source that doesn't exist, or if a date isn't a real date. It then builds every page, checks them (names, links, empty sections, the sitemap), and says "All checks passed". Commit everything it changed, then push.

GitHub Actions publishes `public/` on every push to `main`. Before publishing it runs `node build.js --verify`, which rebuilds the site from the data and stops the run (nothing is published) if `public/` doesn't match.

### Web addresses
Each person's address is saved in the data as `slug` the first time the builder sees them, so correcting a name later doesn't move the page. To change an address on purpose, put the old one in that person's `oldslugs` list; the old address then forwards to the new one.

### Other files
- `src/`: the visualizer's code (`shell.html`, `v3.css`, `v3-extra.css`, `js/`), the person-page styles (`person-pages.css`), the seal glyphs (`glyphs.json`, regenerated by `src/seal_glyphs.py` when new Chinese names are added) and the browser test scripts (`test.js`, `shot.js`).
- `tools/`: records of one-off data changes. They have already been applied; don't run them again.
